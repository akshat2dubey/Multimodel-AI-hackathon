  2. GLOBAL ENGINEERING RULES
            (apply to EVERY task)

  1. Minimal diff. Change only what the task names. No refactors. No new dependencies unless the task says so
     (use what is in requirements.txt; allowed new dev-only dep: pytest).

  2. Keep contracts. Keep CLI flags, output file names and JSON keys that other scripts or dashboard/app.py
     read. If one must change, grep the whole repo for all consumers and update them in the same commit.

  3. Never fabricate data or silently fall back to synthetic data. Fail loudly with a clear message. Synthetic data is
     allowed only inside tests/ or demo/ and must carry a visible banner.

  4. Stay fast. No per-feature full-raster operations; no O(N×M) loops where a window / KD-tree / vectorised op
     works. Prefer numpy/scipy/rasterio/geopandas already installed.

  5. Everything generic. No hardcoded area names, dates, coordinates, or snapshot dates in code. They come from
     results/run_meta.json (see T04).

  6. Empty-safe. Every script must handle zero buildings/roads/bridges/hospitals and produce a valid empty result
     with exit code 0.

  7. Windows-safe. Judges may use Windows: use pathlib, UTF-8 everywhere, no bash-only steps.
  8. Security by default (see tasks T05­T22, T34­T39): no secrets in code/logs, validated inputs, no debug, no

     tracebacks to users.
  9. After each change run the touched script on a tiny input and show real output. Never claim a fix works without

     running it.
10. If something is impossible with the allowed data/time, say so and record it as a limitation in

     docs/LIMITATIONS.md instead of faking it.
